# 旅序 TripWeave（本地原型）

以 IM 对话收集旅行条件，确认简报后用 Pi Durable 执行规划；完成后，聊天卡片可切换右侧行程地图面板，并可打开独立 HTML 行程页。多个旅行会话互相独立，保存在本机。

## 运行

需要 Node.js **22.19 或更高版本**。安装依赖后分别启动 API 和前端：

```bash
npm install
npm run server
```

另开一个终端：

```bash
npm run dev
```

打开 `http://127.0.0.1:5173/`。默认 API 为 `http://127.0.0.1:4321/`，Vite 开发服务器会代理 `/api` 请求。本仓库也安装了本地 Node 22.19；如果系统 Node 版本较低，可以直接使用 `./node_modules/node/bin/node` 执行 `tsx`、`vite`、`vitest` 和 `tsc` 的入口文件。

## 配置与隐私

在页面右上角“配置”中输入兼容 OpenAI Chat Completions 的 HTTPS Base URL、模型名称和 API Key，以及高德 Web 服务 Key。浏览器地图还需高德 JS API Key 和 JS 安全密钥，并应在高德控制台限制可用域名。模型 API Key 与高德 Web 服务 Key 仅保存在 `work/data/settings.json` 并只向客户端返回“已配置”状态；JS 地图凭证必须交给浏览器 SDK，不能视为服务端秘密。数据目录可用 `TRIPWEAVE_DATA_DIR` 覆盖。

`work/data/` 被 Git 忽略。应用仅监听本机回环地址；它没有账号体系或远程多用户隔离，不应直接公开部署。

## 当前能力与限制

- 多轮问询收集出发地、目的地、日期、天数、人数、预算、兴趣和生活/行动限制。简报可在界面中直接修改；保存修订后需重新确认才会规划新版本。规划中可以切换其他会话。
- 单个会话可重命名、归档或移入回收站；归档和回收站中的会话都能恢复，回收站数据不会自动永久删除。规划状态通过实时事件流更新，断线后可重新获取快照。
- 高德 Web 服务提供真实地点坐标和步行路线，模型仅从检索到的地点 ID 中排序；Pi Durable 的 SQLite 任务状态可在重启后重新接续。
- 高德驾车和公交路线可作为交通备选；行动受限时优先驾车，但这不等于景点本身已经过无障碍核验。
- 生成逐日节点、地图标记、攻略文字和独立 HTML 页面；行程卡片点击打开 50% 宽度面板，再次点击关闭。聊天中的地点快捷按钮可直接定位到右侧对应节点卡片。小屏使用全宽面板和会话选择器。
- 没有凭证时不会虚构联网行程，而是给出可重试的配置提示。
- **尚不支持实际下单或支付。** HTML 中的机票、火车票、酒店入口是第三方搜索首页及可复制的查询条件，不保证外站自动预填。用户需要在外站自行核实和完成预订。
- **费用不是报价。** 按已确认的数据策略，当前只使用高德地点、坐标、路线及可用配图；地点名称、地址、坐标和配图记录高德来源及抓取时间。门票价格、开放时间和预约规则在每个景点卡片与 HTML 中标为“待核实”，AI 游览建议也标明未经景区核实。预算只展示用户上限和已知费用，不代表可行性已核验。请在出行前以景区及供应商官方渠道为准。
- 当前路线为每日至多两个景点的市内串联；会按地点邻近程度配对，路线不可达时尝试其他候选地点，并可根据行动限制选用驾车或公交路线。但尚不包含完整跨城机酒组合、可核验的替代行程展示或无障碍路线验证。
- 测试覆盖服务、数据、接口和主要 React 交互；尚未完成真实浏览器端到端验收。当前不会接入额外景点资料或实时价格数据源，因此开放/预约规则与预算可行性保持未核实状态。
